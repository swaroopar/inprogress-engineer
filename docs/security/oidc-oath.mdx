# OAuth and OIDC

OIDC and OAuth are often used as if they mean the same thing.
It helps to know the difference.
A clear mental model keeps the concepts straight.

:::warning Main difference

- **OAuth** - It's only about authorization.
  It manages **authorization** to API resources.
- **OIDC** - It's about authentication.
  It builds on OAuth. It runs once the user is authenticated.
  :::

<ThemeImage src='/img/security-oauth-oidc.excalidraw.png' alt='OIDC vs OAuth' />

1. OIDC is about the authentication flow.
   After authentication, it emits an **ID Token** with user information.
   It also adds standards for the API endpoints of identity providers.

2. OAuth is about granting access to resources without a regular login.
   Identity providers issue **access tokens**. A token is just another form of the user.
   It says which resources the user can access.

:::important OAuth first or OIDC first?
OAuth existed first. OIDC was added on top, using the standards OAuth had set.

OAuth had already defined the flows to get access tokens from identity providers.
OIDC just added the authentication layer and used it to get ID tokens.
:::

:::danger JWT tokens aren't encrypted but digitally signed
Note that both ID tokens and access tokens are
just **base64 encoded** strings. They aren't encrypted.

Still, they're digitally signed with private keys.
Clients verify the signature with public keys to check the tokens are valid.
:::

## Pure OIDC use cases

In case of LinkedIn using Google to log in:

1. Uses OIDC to authenticate the user using Google.
2. Gets back an ID token from Google which contains user information.
3. LinkedIn can use this information to map the user to its user data.
4. It then uses its own authorization to connect to its APIs.

:::warning No OAuth used at all
In this whole flow, no OAuth is used.
It does receive access tokens. But it never uses them to reach Google's services or
its own APIs.
:::

## ID Token vs Access Token

1. **ID Token** - It refers to identity token.
   It contains information about the user.
2. **Access Token** - It refers to the access the user has.
   It contains the authorization information of the user.

:::important Which token is returned when?
ID Token is part of the OIDC standards and access token is part of the OAuth standard.
In case of a full OAuth flow, both tokens are returned.
:::

## Machine to Machine

OAuth 2.0 also enables authorization between two machines without any user interaction.
This is called **client credentials flow**.

Here the client is also authenticated/identified but no OIDC flow is involved.

:::tip Client in OAuth
Client in OAuth always means a machine.
Only user means a human user.
This is why the client_id and client_secret are always for a machine.
:::
